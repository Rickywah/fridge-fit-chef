# Fridge Fit Chef — 产品需求文档（PRD）

## 1. 背景与目标

健身人群常面临：**冰箱有什么、这一顿该怎么吃、宏量是否达标**。本产品以「单餐决策」为切入点，降低计划负担，并支持家人协作维护库存。

**成功指标（MVP）**

- 用户能在 30 秒内完成「填库存 → 生成这顿 → 看步骤」
- 无合适菜谱时仍有可执行的「新的尝试」方案
- 两人共享同一 room 链接时，库存变更在 5 秒内可见（Supabase Realtime）

## 2. 用户画像

| 角色 | 需求 |
|------|------|
| 健身本人 | 按 P/C/F 目标快速出一顿饭，扣减库存 |
| 家人（如妈妈） | 用手机更新冰箱，与本人看到同一份库存 |
| 产品/AI PM 演示 | 规则引擎 + fallback agent + 协作 sync 的 portfolio 故事 |

## 3. 核心用户故事

1. **作为用户**，我想根据现有库存生成一顿符合今日活动量的餐，以便不用自己算宏量。
2. **作为用户**，当没有完整菜谱匹配时，我想得到临时组合与营养区间，以便仍有可参考的做法。
3. **作为用户**，我想复制链接给家人，以便共同维护冰箱。
4. **作为用户**，我想导出 JSON 备份，以便换机或误删后恢复。

## 4. 功能范围

### In scope（v1）

- 四 Tab：今天 / 冰箱 / 菜谱 / 我的
- 单餐推荐（`MEAL_RATIO ≈ 0.40` 日目标）
- 换一套、排除已看过组合
- 标记完成 → 扣减库存
- 自定义食材、菜谱；批量导入
- localStorage 离线优先
- 可选 Supabase room 同步
- 使用统计与 JSON 导入导出

### Out of scope（v1）

- 用户账号登录
- 精确营养数据库 / 扫码
- 真正的 LLM API 调用（adhoc 为本地规则引擎）
- 生产级 RLS 与冲突合并策略

## 5. 非功能需求

- 单 HTML 文件可离线打开（Supabase 为可选增强）
- 移动端优先布局
- 自定义名称展示需 XSS 转义（`escapeHtml`）
- 视觉：**Open Fridge Glow**（训练状态主题 + P/C/F 圆环）；改 UI 不破坏离线与推荐逻辑

## 6. 开放问题

- 多设备同时编辑同一 room 的冲突策略（当前：last-write-wins + Realtime 推送）
- 是否引入 Auth 绑定 room 所有者
